# MatchPulse-Sports

منصة رياضية متعددة المنصات لعرض **مباريات كرة القدم الحقيقية** وتحليل احتمالاتها بطريقة قابلة للتفسير. يجمع المشروع بين واجهة ويب خفيفة، خادم Node.js، وتطبيق Android مبني عبر Capacitor. لا يعرض المشروع مباريات وهمية، ولا يقدّم الاحتمالات كضمان للنتائج أو كنصيحة مراهنة.

## المزايا

تعرض لوحة MatchPulse جدولًا حقيقيًا من `football-data.org` مع الموعد والبطولة والفرق والحالة، وتدعم التصفية حسب البطولة والحالة والترتيب الزمني والتحديث اليدوي. يعرض شريط المؤشرات عدد المباريات الظاهرة، المباريات المباشرة، نسبة البطاقات المحللة، ومصدر البيانات. لكل مباراة نافذة **OBTA** تتضمن احتمالات صاحب الأرض والتعادل والضيف، الثقة، مصدر البيانات، ومنهج الحساب.

تستخدم ألوان OBTA كإشارة بصرية فقط: **الأخضر** لاحتمال أعلى، **الأصفر** لاحتمال متوسط، و**الأحمر** لاحتمال منخفض أو عامل مخاطرة. لا تعني هذه الألوان نتيجة مؤكدة. الواجهة ثنائية اللغة وتبدّل اتجاه الصفحة بين العربية والإنجليزية.

## تقويم المباريات Pro

تظهر لوحة **تقويم المباريات Pro** داخل مسار عرض المباريات. يستطيع المشترك اختيار مباريات محددة أو تصدير المباريات المعروضة حاليًا بعد تطبيق المرشحات. ينشئ الخادم ملف `ICS` متوافقًا مع RFC 5545؛ يتضمن لكل حدث موعد `UTC` والفرق والبطولة ومصدر البيانات المعروف فقط. لا يحتوي التصدير على احتمالات أو رهانات أو نصائح مالية.

الواجهة لا تعتبر `localStorage` أو رابطًا أو زرًا دليلًا على الدفع. قبل أي تنزيل تستدعي `GET /api/pro/entitlement`، ثم ترسل الطلب إلى `POST /api/pro/calendar/export`. كلاهما يفشلان مغلقين افتراضيًا: الخادم الحالي يعيد `purchase_setup_required` ولا ينزّل ملفًا حتى يصل تكامل الحسابات والاشتراك الحقيقي.

قبل الإطلاق، يجب أن يزوّد تكامل المصادقة/الدفع الخادمي `createServer({ verifyEntitlement })` بحالة مستمدة حصريًا من جلسة مستخدم موثقة وسجل اشتراك دائم تم التحقق منه من مزود الدفع. يجب أن تُرجع الدالة فقط `{ entitled: true, status: 'active', subject }` عند اشتراك نشط؛ ولا يجوز تمرير هوية أو استحقاق من المتصفح. لا يوجد شراء أو مزود أو سعر أو تفعيل يدوي مهيأ في هذا المستودع بعد.

## التشغيل على الويب

يتطلب التشغيل Node.js 20 أو أحدث. انسخ قالب البيئة إلى ملف محلي، ثم أضف الرمز في بيئة الخادم فقط:

```bash
cp .env.example .env
# عدّل .env محليًا ولا ترفعه إلى GitHub
npm install
npm start
```

بعدها افتح `http://localhost:8787`. نقاط الخادم الأساسية هي `GET /api/health` و`GET /api/matches?status=SCHEDULED`. الخادم هو الطرف الوحيد الذي يتعامل مع `FOOTBALL_DATA_TOKEN`؛ لا يُرسل الرمز إلى المتصفح.

## تشغيل Android

المشروع مجهّز بمنصة Android أصلية عبر Capacitor. لتحديث ملفات الويب داخل الحزمة ثم مزامنتها مع Android:

```bash
npm install
npm run mobile:sync
```

لتحديث الواجهة فقط داخل النسخة المضمّنة استعمل `npm run mobile:build`. لا يُعد ذلك تكاملًا مع Google Play Billing أو شراءً داخل التطبيق. يلزم تحديد قناة توزيع Android ومزود الدفع قبل تركيب بوابة الاستحقاق المناسبة.

لفتح المشروع في Android Studio:

```bash
npm run mobile:open
```

يتطلب بناء APK وجود Android Studio وAndroid SDK وJava 17 على جهاز البناء. بعد فتح مجلد `android` في Android Studio، اختر **Build > Build APK(s)**. لا يحتاج التطبيق إلى وضع مفتاح API داخله؛ يجب أن يشير إلى خادم MatchPulse المنشور الذي يحمي المفتاح في بيئته الخلفية. لم يتم تضمين ملفات keystore أو أسرار توقيع داخل المستودع.

## الفحص والاختبارات

```bash
npm run check
npm test
npm run test:secret
```

يتحقق الفحص من صياغة الخادم والواجهة ومولد ICS. تتحقق الاختبارات من صيغة التقويم (UTC وCRLF والهروب)، وترفض المصدر أو التاريخ غير الصالح، وتؤكد أن بوابة Pro لا تصدر الملف عند غياب استحقاق خادمي. يتطلب `test:secret` رمز مزود بيانات صالحًا في البيئة؛ لا تضعه في Git.

## البيانات والمنهجية

يستخدم الإصدار الحالي مصدرًا خارجيًا حقيقيًا من خلال `football-data.org`. طبقة الاحتمالات الحالية baseline تفسيرية وليست نموذجًا مدربًا على بيانات تاريخية. قبل اعتمادها كنظام تنبؤ إنتاجي، يجب إضافة بيانات تاريخية مرخّصة، تقسيم زمني للتدريب والاختبار، معايرة احتمالات، وقياسات مثل Brier score وlog loss.

## الخصوصية والاستخدام المسؤول

لا تضع `FOOTBALL_DATA_TOKEN` أو أي رمز وصول في الواجهة أو ملفات Git أو تطبيق Android. استخدم متغيرات بيئة سرية على خادم الخلفية، وراجع `.gitignore` قبل كل رفع. لا ينبغي استخدام الاحتمالات كضمان أو كأساس وحيد لقرار مالي أو مراهنة؛ كرة القدم غير يقينية وقد تؤدي القرارات المبنية على التحليل إلى خسارة المال.

## هيكل المشروع

| المسار | المسؤولية |
|---|---|
| `server.mjs` | خادم Node.js، جلب البيانات، وبوابة تقويم Pro الفاشلة مغلقًا |
| `lib/calendar-ics.mjs` | مولّد RFC 5545 بمدخلات محدودة، UTC، CRLF، وهروب نصي |
| `public/index.html` | هيكل لوحة الرياضة ولوحة تقويم Pro ونافذة OBTA |
| `public/app.js` | الجلب، التصفية، الترجمة، الاختيار، وطلب التصدير المحمي |
| `public/styles.css` | الهوية البصرية، ألوان التحليل، وتجربة التقويم المتجاوبة |
| `android/` | مشروع Android الناتج عن Capacitor |
| `capacitor.config.json` | هوية التطبيق ومجلد الويب المحمول |
| `.env.example` | قالب متغيرات آمن بلا قيم سرية |
